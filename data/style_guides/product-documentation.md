# Product documentation style guide

## Voice

- Use direct, calm language and address the reader as "you".
- Prefer active voice and present tense.
- Explain what a feature does before describing its benefits.
- Keep claims limited to the supplied product evidence.

## Structure

- Use sentence case for headings.
- Put prerequisites before procedural steps.
- Write numbered steps for tasks that must be completed in order.
- Use bullets for unordered details and limitations.

## Technical writing

- Preserve product names, role names, UI labels, dates, and limits exactly.
- Use code formatting for commands, paths, API names, and literal values.
- State unsupported or unknown behavior as unknown; do not infer it.
- Include a source reference for each material product claim when available.
