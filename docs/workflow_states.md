# Workflow states

```
intake -> context_preparation -> review -> approved -> published
                                   |  ^
                                   v  |
                         revision_requested / refine / edit (new draft version, back to review)
review -> rejected          any AI error -> failed (retry with POST /run)
```

| State | Meaning |
| --- | --- |
| intake | Job created with source text or an uploaded document |
| context_preparation | Source normalized; context pack (facts, gaps, contradictions) being built |
| review | Draft generated by the agents; waiting for a human decision |
| revision_requested | Reviewer sent it back; a refined version is produced |
| approved | An approver/admin approved the draft (required before export) |
| published | Exported (Markdown with front matter or CMS JSON; optional GitLab MR) |
| rejected / failed | Rejected by a reviewer / workflow error (state preserved, retry allowed) |

## Agent stages
1. **Context Reader** - extracts facts, gaps, contradictions and source references. Fails visibly (`422`) if no supported facts exist.
2. **Documentation Writer** - drafts from approved context only, using the GitLab voice guide and the template for the content type.
3. **Technical Reviewer** - checks each claim against the evidence; a deterministic grounding guard also flags versions, API paths and metrics that are not in the source.
4. **Tone Optimizer** - audience and channel fit, no new facts.
5. **Publishing Coordinator** - clean customer-facing Markdown plus source references.

Each run records the agent trace (status and seconds), prompt version and orchestrator (`crewai` or `direct`) in the audit log. Single stages (tone, structure, clarity, technical) can be re-run from the review screen without restarting the workflow.
